# 📜 RULES — манифест ИИ-агента

> Базовые законы работы в этом репозитории. Действуют для любой задачи и любого
> инструмента (Cursor, Claude, Copilot, Codex, локальные агенты).
> Файл универсален: всё, что относится к конкретному проекту, помечено `[ ... ]`
> и заполняется один раз при старте проекта.

---

## 0. Порядок входа в проект

1. Прочитать `README.md` (корень) — это инструкция верхнего уровня.
2. Прочитать `.ai/MEMORY.md` — состояние проекта и предыдущие решения.
3. Прочитать `.ai/RULES.md` (этот файл) — законы работы.
4. Развернуть скиллы из `.ai/skills.txt` (если файл не пуст) — до первой правки кода.
5. Только после этого читать код и писать код.

Если шаги 1–4 не выполнены, любые изменения считаются несогласованными.

## 1. Чистота кода

- Пиши **минимальный достаточный** код. Нет задачи — нет абстракции, нет «на будущее».
- Одна функция — одна ответственность; имя описывает результат, а не процесс.
- Никаких «магических» чисел и строк: константа или переменная с понятным именем.
- Не оставляй закомментированный код, отладочные `print`/`console.log`, мусорные импорты.
- Соблюдай стиль, уже принятый в проекте, даже если он не совпадает с твоими привычками.
- Ошибки обрабатывай явно: у пользователя должен быть понятный результат, а не пустой экран.

## 2. Не ломать существующее

- **Не удалять и не переписывать функции/фичи без аргументации в `.ai/MEMORY.md`.**
  Запись обязательна, если меняется поведение, а не только косметика.
- Перед удалением: найти все места использования (`grep` по проекту), оценить последствия,
  предложить замену или миграцию.
- Публичные контракты (API, схемы БД, форматы событий, env-переменные) меняются только
  с обратной совместимостью либо по прямому указанию владельца.
- Чужие папки и файлы вне задачи не трогай, даже если «так было бы красивее».
- Не переименовывай существующие каталоги «для порядка» — это ломает ссылки, CI и деплой.

## 3. Бережное отношение к контексту

- Не читай файлы целиком, если нужен фрагмент: используй поиск, диапазоны строк, символы.
- Не вставляй в ответ большие блоки кода и логи — цитируй только релевантное.
- Не выполняй «разведочные» правки ради проверки гипотезы: сначала чтение и анализ.
- Держи `.ai/MEMORY.md` компактным: одна строка на старое решение, детали — в истории коммитов.
- Если задача требует больше контекста, чем доступно, — остановись и спроси, а не угадывай.

## 4. Логирование и наблюдаемость

- Новый значимый сценарий сопровождается логом: что произошло, с какими параметрами, с каким итогом.
- В логах **не должно быть** секретов, токенов, паролей, полных персональных данных.
- Ошибки логируются один раз, на границе обработки, — без каскада дублирующих сообщений.
- Уровни осмысленно: `error` — требует реакции, `warn` — деградация, `info` — бизнес-событие,
  `debug` — только для локальной диагностики.

## 5. Безопасность и данные

- Секреты живут только в переменных окружения/хранилище секретов; в коде — только имена.
- Любой внешний ввод валидируется на границе (тип, диапазон, размер, формат).
- Права проверяются на сервере, а не в интерфейсе.
- Деструктивные операции (удаление данных, миграции, `rm -rf`, force-push) — только по явному
  подтверждению владельца, с предварительной резервной копией или планом отката.

## 6. Работа с Git

- Одна задача — одна ветка; имя ветки отражает смысл (`feat/...`, `fix/...`, `chore/...`).
- Коммит — законченное изменение, сообщение в императиве: `feat: ...`, `fix: ...`, `docs: ...`.
- В коммит не попадают: секреты, `.env`, `node_modules`, артефакты сборки, кэши, временные файлы.
- `push --force` в общие ветки запрещён.
- Перед коммитом: проверки (линт/типы/тесты), `git diff` глазами, обновлённый `.ai/MEMORY.md`.

## 7. Definition of Done

Задача считается выполненной, только если:

- [ ] Поведение соответствует критериям приёмки из брифа (`PROMPTS/`).
- [ ] Линт, типы и тесты проекта проходят (или явно объяснено, почему нет).
- [ ] Изменения проверены запуском, а не только чтением кода.
- [ ] Обратная совместимость сохранена либо описана миграция.
- [ ] В `.ai/MEMORY.md` добавлена запись в ARGUMENTATION LOG и обновлён CURRENT PROJECT STATE.
- [ ] В отчёте владельцу: что сделано, чем проверено, что осталось и какие риски.
